# Amend is deferred and rebuilds HEAD via `commit-tree`, never a soft reset

**Status:** accepted

Amend in Rebase rewrites HEAD with the user's full power — reword, fold in staged changes, and *drop* files that were already in the commit (their content falling back to the working tree). Two invariants shape how it runs. First, **nothing mutates until the user commits**: ticking the amend toggle must not touch the repository, so that un-ticking is a perfect no-op ("as if I never pressed it") and a half-finished amend can never strand the last commit one step back in the reflog. Second, the rewrite must be **atomic and merge-safe**. The naive implementation — `git reset --soft HEAD~1` then re-commit — violates both: it moves HEAD to the parent for a real (if brief) window where a crash leaves the branch stranded, it silently resolves `HEAD~1` to the *first parent* of a merge commit (dropping the merge), and it needs the original author re-supplied by hand. So at commit time the sidecar instead builds the new commit as an object and swaps it in last: construct the desired tree in a throwaway index (the real index's tree, with **each dropped path reverted to its parent-commit state** — not merely deleted: dropping reverts to `HEAD~1`'s version, so an *added* file vanishes, a *modified* file falls back to the old content, a *deleted* file reappears, matching `git restore --staged --source=HEAD~1`) → `write-tree` → `commit-tree <tree> -p <parent…>` carrying **every** original parent and the preserved author → `update-ref HEAD <new> <old>` as a **compare-and-swap** → `reset --mixed` so each dropped path's HEAD version surfaces as a working-tree change. HEAD moves exactly once, at the very end, and only if it still points where we started.

## Considered options

- **`commit-tree` + CAS `update-ref` (chosen).** HEAD moves once, atomically. The `update-ref HEAD <new> <old>` refuses if HEAD moved underneath us — the same defense ADR 0006 built against the background-fetch race for force-push (`--force-if-includes`), here against the watcher/auto-fetch/another action advancing HEAD mid-amend. Passing `-p` for each original parent makes amending a **merge commit** correct for free; a root commit is simply `commit-tree` with no `-p`. Cost: plumbing (a temp index via `GIT_INDEX_FILE`, `write-tree`, `commit-tree`, `update-ref`).
- **Mutate on toggle (`reset --soft HEAD~1` when the box is ticked).** Most literally "brings HEAD's changes into the panel," but a *checkbox* would rewrite history: tick-and-walk-away strands the last commit behind a moved HEAD, the Timeline flickers as the tip jumps, and un-ticking has to perfectly reconstruct the original commit. Rejected — non-committal gestures must never write.
- **Commit-time soft reset.** Defers the mutation to the commit click, but still moves HEAD to the parent before the new commit lands (a crash-stranding window, narrowed but real), still drops merges via first-parent `HEAD~1`, and still needs `--author` by hand.

## Consequences

- The CAS refusal is an **expected** outcome, not an error. `amendCommit` returns a tagged `AmendRejected { reason: 'head-moved' }` (mirroring `PushRejected`) so the renderer can say "HEAD changed under you — refresh and retry" instead of showing a scary failure. ⚠️ A new tagged RPC error must be registered in main's `classifyExit` allowlist, or it silently collapses to a generic failure and only e2e catches it.
- Amend stays **orthogonal to push**: it only rewrites HEAD and leaves the branch [[Diverged]] when the amended commit was already published. Republishing reuses the existing two-tier leased force-push (ADR 0006); amend never pushes on its own.
- Author identity and original author date are preserved (set on `commit-tree` via `GIT_AUTHOR_*`); the committer/committer-date advance, matching git's own `--amend` semantics.
- The toggle is unavailable when there is no HEAD (a repo with zero commits) — there is nothing to rebuild.
