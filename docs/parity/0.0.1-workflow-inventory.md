# 0.0.1 workflow parity inventory

This inventory is the executable product contract for the `0.0.2` runtime migration. A row is not
complete because a screen renders: the cited E2E scenario drives the visible workflow, and every Git
write is backed by a temporary real repository. Focused renderer tests cover interaction variants
that share the same command, while sidecar integration tests cover the corresponding native Git
mutation and edge cases.

The default deployment is Electron. All user-workflow specs import the shared `test` and
`AppHarness` from `e2e/fixtures.ts`; they contain no launch code. A browser/WSL deployment supplies
the same harness through `REBASE_E2E_DEPLOYMENT_ADAPTER`, so scenario definitions are reused
unchanged. The four preload/process checks in `app-launches.spec.ts` are explicitly Electron-only and
are not parity scenarios.

## Manual checks

Only behavior that cannot be made deterministic without substituting the operating system or release
infrastructure remains manual:

- native folder-picker appearance, keyboard behavior, and permission prompts on supported Windows,
  macOS, and Linux versions;
- installation of a signed update from each release channel in a packaged build; and
- macOS/Windows visual diff appearance, while Linux is the canonical screenshot platform and all
  platforms retain DOM and palette assertions.

These checks are deployment-shell concerns. No repository mutation or browser-parity workflow is
manual.

## Running against another deployment

An adapter module exports a `DeploymentAdapter` as its default export or as `deploymentAdapter` and
returns an `AppHarness` from `createHarness`. It owns process/browser launch, isolated profile state,
relaunch, viewport sizing, test-state seeding, and folder-selection control. The shared fixture owns
temporary repository creation and cleanup.

```bash
REBASE_E2E_DEPLOYMENT_ADAPTER=/absolute/path/to/wsl-browser-adapter.mjs \
  pnpm playwright test e2e/staging-commit.spec.ts
```

Electron preload and lifecycle assertions self-skip for non-Electron adapters. All visible workflow
scenarios run unchanged.
